# desktop-form-interactions Specification

## Purpose

为当前 Desktop 持久化文本表单和轻量浮层建立可复用、低噪声、无布局抖动且可访问的常规交互契约，并明确其与搜索输入及危险 Dialog 的边界。

## Requirements

### Requirement: 持久化文本表单提供稳定且可访问的字段反馈
Desktop 当前已实现的持久化文本表单 SHALL 按 canonical 产品约束在客户端执行 trim、Unicode NFC 与 Unicode code point 计数，并 SHALL 以 Core API 为最终权威。必填字段在未交互且未提交时 MUST NOT 立即显示错误；规范化后为空的错误 SHALL 在字段失焦或用户提交后出现。对于当前规范化值未超过上限的字段，任何会使完整候选值超过上限的普通键入、选择区替换、粘贴或输入法提交 MUST 被原子拒绝，不得进入保存请求或依赖保存失败恢复；控件 SHALL 保留最后一个已接受草稿、焦点与可继续删除、撤销或替换的编辑能力，并通过稳定状态区提供可感知反馈。字段错误 SHALL 与控件建立可访问关联并进入可感知的错误摘要或公告；提交失败 SHALL 保留草稿、焦点与当前业务上下文。Core Problem Details 包含可识别 `path` 时 SHALL 映射到对应字段，无法映射的错误 SHALL 作为表单级错误展示。提交操作 MUST NOT 仅通过无解释的 disabled 状态表达失败原因。

#### Scenario: 未交互表单保持低噪声
- **WHEN** 用户首次打开包含必填名称或标题的创建表单且尚未交互或提交
- **THEN** 表单不立即显示“不能为空”错误，但字段的必填语义仍可被辅助技术理解

#### Scenario: 失焦后显示必填错误
- **WHEN** 用户触碰必填字段并使规范化后为空的值失焦
- **THEN** 对应字段显示双语可理解错误并与控件建立可访问关联，草稿和其他字段保持不变

#### Scenario: 到达上限后拒绝增长编辑
- **WHEN** 当前字段合法且用户的完整候选编辑会使 trim + NFC 后的 code point 数超过产品上限
- **THEN** Desktop 原子拒绝该候选编辑，保留最后一个合法草稿、焦点与光标上下文，不触发自动保存，并通过稳定状态区说明已达到上限

#### Scenario: 上限处仍可修正内容
- **WHEN** 字段已达到上限且用户删除、撤销或用不超过上限的内容替换选择区
- **THEN** Desktop 接受该完整编辑，继续允许正常输入与后续保存，不把字段锁定为只读或 disabled

#### Scenario: 超限粘贴不被部分截取
- **WHEN** 一次粘贴的完整候选值会超过产品上限
- **THEN** Desktop 拒绝整次粘贴并保留最后一个已接受草稿，不插入可容纳的前缀，也不移动焦点或触发保存

#### Scenario: 输入法组合按提交结果判断
- **WHEN** 用户正在进行 IME composition
- **THEN** Desktop 不干预中间 composition 文本，并在 composition 提交完成时按完整候选值判断；若结果超限则原子拒绝该提交而不切割组合文本

#### Scenario: 历史超长值可以收敛
- **WHEN** 既有字段超过当前产品上限且用户开始编辑
- **THEN** Desktop 完整显示并允许选择该值，接受不超过该编辑会话初始权威值规范化 code point 数的删除、撤销与替换，拒绝超过该历史天花板的增长编辑，并仅在结果回到当前产品上限内后自动保存该字段；未编辑的历史字段不阻塞其他稀疏 mutation

#### Scenario: 暂停未收敛草稿并编辑其他字段
- **WHEN** 历史超长字段已有未保存且仍超过当前上限的收敛草稿，用户激活负责人或另一可独立编辑字段
- **THEN** Desktop 不提交或丢弃该历史草稿，不阻止目标字段进入编辑，并把前者保留为可恢复且明确标记未保存的暂停草稿；目标字段继续以最新权威版本执行只包含自身变化的稀疏 mutation

#### Scenario: 无关保存后恢复暂停草稿
- **WHEN** 另一字段的稀疏 mutation 成功并返回更新后的资源，而暂停草稿对应字段的权威值未变化
- **THEN** Desktop 采用最新资源版本和其他权威字段，同时保留暂停草稿；用户恢复该字段并收敛到当前上限后，使用最新版本保存，不复用暂停时的旧版本

#### Scenario: 暂停字段发生并发变化
- **WHEN** 刷新或另一 mutation 的权威响应表明暂停草稿对应字段已不同于该草稿开始时的权威值
- **THEN** Desktop 保留本地草稿并进入明确冲突处理，不以本地暂停草稿或服务器值静默覆盖另一方，也不声称草稿已保存

#### Scenario: 关闭前处理未收敛草稿
- **WHEN** 用户尝试关闭详情且仍有超过当前上限的暂停草稿
- **THEN** Desktop 保持详情打开并提供“继续编辑”和“放弃并关闭”的明确门禁；继续编辑恢复草稿与焦点，放弃并关闭恢复权威值后关闭，外部点击或普通关闭不得静默丢弃草稿

#### Scenario: 服务端字段错误映射
- **WHEN** 提交后 Core API 返回带有已知字段 `path` 的 validation Problem Details
- **THEN** Desktop 把错误展示在对应字段并保持用户输入、焦点恢复路径和当前 Dialog 或详情上下文

#### Scenario: 错误反馈不造成布局抖动
- **WHEN** 字段在正常、接近上限、错误和 pending 状态之间切换
- **THEN** 标签、控件起始位置、相邻字段和主要操作保持稳定，不因反馈行出现或消失发生明显位移

### Requirement: 字符计数保持低噪声并遵循 Unicode 语义
持久化名称、标题与描述控件 SHALL 按 trim 与 Unicode NFC 后的 Unicode code point 数量判断约束。计数器 SHALL 仅在达到字段上限的 80%、字段达到上限或展示历史超长值时显示，并 SHALL 同时呈现当前值和上限；低于阈值且合法时 MUST NOT 永久占用视觉注意力。正常输入 SHALL 不产生超限计数，因为超限候选编辑已被拒绝；历史超长值 SHALL 显示实际数量和需要收敛到的上限。计数与状态反馈的预留区域 SHALL 保持表单几何稳定。

#### Scenario: 组合字符按规范化结果计数
- **WHEN** 用户输入可由多个 code point 组合成单个 NFC 字符的文本
- **THEN** 客户端计数与 Core API 对规范化结果的计数一致，不按 UTF-16 code unit 或字节数误判

#### Scenario: 接近上限时出现计数
- **WHEN** 规范化值从低于上限 80% 变为达到该阈值
- **THEN** 控件显示“当前值 / 上限”计数而不移动标签、控件或相邻表单内容

#### Scenario: 远离上限时隐藏计数
- **WHEN** 字段合法且规范化长度低于上限 80%
- **THEN** 计数不持续显示，但预留反馈策略仍保证后续出现时不造成明显布局抖动

#### Scenario: 到达上限时提供可访问状态
- **WHEN** 字段达到上限或一次增长编辑因上限被拒绝
- **THEN** 控件显示当前值与上限，并通过不会抢走焦点的稳定 live status 说明已达到上限；相同状态不得在每次按键时产生重复播报噪声

### Requirement: 轻量浮层采用可组合的外部关闭与焦点契约
Desktop 无未保存草稿或危险提交门禁的轻量菜单、popover 与 listbox SHOULD 在触发器及浮层拥有内容之外的 `pointerdown` 关闭，并 MUST NOT 阻止同一次指针操作到达用户实际目标。浮层本体、触发器及其 Portal-owned descendants SHALL 共同视为内部区域。`Escape` SHALL 关闭最上层轻量浮层并把焦点恢复到其触发器。具有脏数据、pending、破坏性确认或显式取消语义的 Dialog MUST 使用自身关闭策略，MUST NOT 因采用轻量浮层规则而丢弃数据或绕过门禁。

#### Scenario: 外部目标一次点击生效
- **WHEN** 轻量浮层打开且用户对外部可操作目标执行 pointerdown/click
- **THEN** 浮层关闭且目标操作在同一次交互中生效，不需要第二次点击

#### Scenario: Portal-owned 内容属于内部
- **WHEN** 用户操作视觉上属于当前浮层但通过 Portal 渲染的选项或子内容
- **THEN** 系统不把该操作误判为外部点击，选项可正常完成自己的行为

#### Scenario: Escape 恢复触发器焦点
- **WHEN** 键盘用户按 `Escape` 关闭最上层轻量浮层
- **THEN** 焦点返回其仍存在且可操作的触发器

#### Scenario: Dialog 保持独立门禁
- **WHEN** 用户在具有脏输入、pending 或危险确认的 Dialog 外部按下指针
- **THEN** Dialog 按自身明确规则处理，不因轻量浮层默认值静默关闭、丢弃草稿或提交危险操作

### Requirement: 表单规则只覆盖已实现的持久化业务字段
本能力 SHALL 审计首次注册显示名称、Project 创建与设置、Board 创建与编辑、Column 创建与编辑、Work Item 创建与详情编辑这些当前已实现入口。搜索、筛选、纯本地临时输入与精确名称删除确认 MUST NOT 被误当作普通持久化字段套用产品写入上限。永久删除确认 SHALL 接受用户完整输入历史名称并按权威名称精确比较，即使该历史名称超过当前新写入上限。系统 MUST NOT 为尚不存在的设置页面或业务入口伪造表单，也 MUST NOT 仅为统一外观引入跨项目表单框架。

#### Scenario: 搜索输入不套用领域名称上限
- **WHEN** 用户在搜索或筛选控件输入文本
- **THEN** 控件按其本地查询语义工作，不把 Project、Board、Column 或 Work Item 写入上限误报为领域 validation error

#### Scenario: 历史长名称仍可确认删除
- **WHEN** 既有 Board 或 Project 的名称超过当前产品写入上限且用户进入永久删除确认
- **THEN** 确认控件允许输入并精确匹配完整权威名称，不截断，也不要求先编辑名称

#### Scenario: 不存在的表单不纳入实现
- **WHEN** 审计发现某类设置或创建入口当前没有可运行实现
- **THEN** 本 Change 不创建占位页面或伪 API，只记录并验证当前可达入口
